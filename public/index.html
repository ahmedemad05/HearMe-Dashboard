SERIAL PROTOCOL — JSON LINES

One JSON object per line, UTF-8, terminated by \n, at the configured baud rate (default 115200; firmware must match). Unknown types and malformed lines are ignored. Fields not sent display as N/A. Untested against real hardware.

DEVICE → DASHBOARD

{"type":"telemetry","device":"ESP32-S3","firmware":"0.1.0","uptime_ms":120000,
 "battery_voltage":4.12,"battery_percent":95,"free_psram":8192000,"total_psram":8388608,
 "rms":0.042,"samples":[...optional int/float array...],"latency_ms":118}
{"type":"detection","event":"doorbell","confidence":0.924,"latency_ms":118,"haptic_pattern":"doorbell"}
{"type":"ack","command":"test_doorbell","status":"success"}

Events: doorbell, name_call, fire_alarm, unknown. Only detection packets create log rows; telemetry never does. samples (optional) enables a true waveform; otherwise an RMS trace is drawn and labelled as such.

FIRMWARE CHANGES REQUIRED

  • Emit telemetry at \~10–20 Hz with RMS computed from INMP441 I²S frames.
  • Emit detection packets once per confirmed classification.
  • Parse command lines, drive the vibration motor, reply with an ack only after the pattern starts.
  • Battery percentage only if the cell chemistry/ADC calibration is known.

HARDWARE TEST CHECKLIST

  • Connect over USB in Chrome/Edge (Web Serial needs HTTPS or localhost; assets can then run offline).
  • Verify telemetry updates, RMS responds to speech, N/A for missing fields.
  • Verify each haptic test produces a motor pattern and an ack; unplug mid-session.
